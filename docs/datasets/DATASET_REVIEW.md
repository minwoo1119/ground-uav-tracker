# DroneDetectionThesis 데이터셋 적합성 분석 및 검토 보고서

## 1. 개요 및 목적

본 문서는 지상 고정 RGB 카메라 기반 소형 드론 탐지·추적 시스템의 1차 학습 및 검증용 후보 데이터셋인 **DroneDetectionThesis(Halmstad University)** 데이터셋의 적합성을 체계적으로 검증한 기술 보고서입니다.

- **데이터셋 저장소**: [DroneDetectionThesis/Drone-detection-dataset](https://github.com/DroneDetectionThesis/Drone-detection-dataset)
- **원저자 및 논문**: Fredrik Svanström et al. (Halmstad University), *"A Dataset for Multi-Sensor Drone Detection"*, Data in Brief (2021) / ICPR 2020.
- **검토 목적**:
  1. 지상 고정 RGB 카메라 기반 소형 드론 탐지·추적 목표에의 부합 여부 검증
  2. 영상 및 라벨 파일 구조, 크기, 클래스별 분포 분석
  3. MATLAB `.mat` 라벨의 Python 파싱 가능성 및 `mcos-decoder` 호환성 심층 검증
  4. Bounding Box 구성 및 Tracking ID 지원 여부 확인
  5. 카메라 모션(움직임) 존재 여부 및 고정 카메라 모델 학습 영향 분석
  6. 영상 단위 데이터 분할 전략 및 라이선스/재배포 조건 확인

## 3. MATLAB `.mat` 라벨 구조 및 Python 파싱 방안

### 3.1 MATLAB `groundTruth` MCOS 직렬화 문제

라벨 파일(`.mat`)은 단순한 MATLAB 행렬이나 구조체(struct)가 아닙니다. MATLAB Computer Vision Toolbox의 `groundTruth` MCOS(MATLAB Class Object Storage) 객체로 저장되어 있습니다.

- **표준 파이썬 라이브러리의 한계**:
  `scipy.io.loadmat`, `pymatreader`, `mat73` 등으로 로드할 경우 `gTruth` 변수는 메타데이터 헤더만 담긴 `MatlabOpaque` 객체로 반환되며, 실제 프레임별 Bounding Box 데이터는 내부 바이너리 버퍼인 `__function_workspace__`에 압축되어 은닉됩니다.
- 이는 저장소 Issue #3 및 SciPy issue #22736으로도 보고되어 있으며, 일반적인 파이썬 스크립트로는 접근이 불가능합니다.

### 3.2 Python 해석 방안 비교 및 채택 결과

| 방안 | 설명 | 장점 | 단점 | 채택 여부 |
|---|---|---|---|---|
| **A. `mcos-decoder` (PyPI)** | 순수 파이썬 MAT5 스트림 역공학 라이브러리 | 외부 의존성 최소, MATLAB 불필요 | **Video_V 및 복수 객체 프레임에 심각한 호환성 결함 존재** (아래 4절 상술) | 미채택 |
| **B. `mat-io` (PyPI)** | MCOS 범용 파서 | 범용 MCOS 속성 트리 탐색 가능 | 무거운 의존성, `groundTruth` 특화 추출 로직 직접 구현 필요 | 미채택 |
| **C. MATLAB 공식 엔진/변환 스크립트** | MATLAB 런타임을 이용해 CSV/JSON으로 일괄 익스포트 | MathWorks 공식 API로 무결성 보장 | MATLAB 라이선스 필수, 자동화 파이프라인 구축 어려움 | 미채택 |
| **D. 저장소 내장 경량 MAT5 전용 파서 (`scripts/mcos_parser.py`)** | MAT5 바이너리 스트림을 5열 스트라이드 + 열 우선(Column-major) 행렬로 직접 디코딩 | 의존성 제로(표준 라이브러리만 사용), Video_V/IR 및 다중 객체 완벽 호환 | 파서 자체 유지보수 | **채택 및 구현 완료** |

## 4. `mcos-decoder`의 호환성 검증 결과 (중요 발견)

저장소 README에 안내된 `mcos-decoder`(Burak Ozdemir, 2026)의 호환성을 검증하기 위해 바이너리 MAT 스트림을 역공학하여 심층 분석하였습니다.

### 4.1 핵심 발견 사항 (Critical Finding)

> [!WARNING]
> `mcos-decoder`는 5열 타임테이블 구조를 무시하고 바이트 크기(`80B` / `112B`)만으로 휴리스틱 파싱을 수행하므로, **Video_V(RGB)뿐만 아니라 Video_IR의 2개 이상 객체 프레임까지 누락하거나 오분류**합니다.

#### 결함 원인 분석

1. **MATLAB `LabelData` 타임테이블의 열(Column) 구성**:
   MATLAB `groundTruth`의 타임테이블은 5개 열로 구성됩니다:
   - `Col 0`: Time (타임스탬프 메타데이터, 72바이트)
   - `Col 1`: AIRPLANE (`48B` 빈 셀 또는 `48 + 32*N` 바이트 N개 bbox)
   - `Col 2`: BIRD (`48B` 빈 셀 또는 `48 + 32*N` 바이트 N개 bbox)
   - `Col 3`: DRONE (`48B` 빈 셀 또는 `48 + 32*N` 바이트 N개 bbox)
   - `Col 4`: HELICOPTER (`48B` 빈 셀 또는 `48 + 32*N` 바이트 N개 bbox)

2. **`mcos-decoder`의 단순 순회 및 `112B` 오해**:
   - MATLAB 바이너리에서 빈 셀(`0x0 double`)은 `48B`, 1개 박스는 `80B (1x4 double)`, 2개 박스는 `112B (2x4 double)`, 3개 박스는 `144B (3x4 double)`, 4개 박스는 `176B`, 5개 박스는 `208B`로 저장됩니다.
   - `mcos-decoder`는 `112B`를 빈 프레임(`None`)으로 하드코딩하고 `48B`와 `144B` 이상은 무시합니다.
   - 실제 확인 결과 `IR_BIRD_001`의 `112B` 셀(74프레임) 역시 빈 셀이 아니라 **조류 2마리가 동시에 찍힌 `2x4 double` 행렬**이었습니다. 즉 `mcos-decoder`는 2개 객체가 등장하는 프레임을 모두 빈 프레임으로 버립니다.

3. **MATLAB 열 우선(Column-Major) 저장 순서**:
   - 한 프레임에 동일 클래스 객체가 $N$개일 때 MATLAB은 $N \times 4$ 행렬을 `[x1..xN, y1..yN, w1..wN, h1..hN]` 열 우선 순서로 직렬화합니다.
   - 이를 행 우선으로 읽으면 $N \ge 2$인 모든 프레임에서 좌표가 뒤섞입니다.

### 4.2 기술적 대응 결과

`scripts/mcos_parser.py`에서 **행 단위 5열 스트라이드(Stride)**와 **열 우선 `(N x 4)` double 배열 언패킹**을 구현하여 Video_V 285개 전수 파일(89,233 프레임, 96,245 BBox)이 누락 없이 파싱됨을 검증하였습니다.

## 5. Bounding Box 구성 및 Tracking ID 유무

### 5.1 Bounding Box 구성 형식

- **좌표 체계**: `[x, y, width, height]` (MATLAB 표준 픽셀 좌표계)
- **자료형**: 64비트 부동소수점 (`double`, 8바이트 x 4 = 32바이트)
- **기준점**: `(x, y)`는 경계 상자의 좌상단(Top-Left) 모서리 픽셀 위치이며, `width`와 `height`는 픽셀 단위 너비와 높이입니다.

### 5.2 Tracking ID 존재 여부

- **Tracking ID 없음 (미존재)**:
  - 원본 라벨 파일 내부에는 각 프레임별 `[x, y, w, h]` 좌표만 존재하며, 객체 추적 식별자(Track ID) 필드는 존재하지 않습니다.
- **처리 전략 (`scripts/convert_dataset.py`)**:
  - 전체 89,233 프레임 중 단일 객체 프레임이 84,768개(95.0%), 빈 프레임이 82개(0.09%), 다중 객체 프레임이 4,383개(4.91%)입니다.
  - 마스터 JSON 및 MOT 포맷 변환 시 연속 프레임 간 클래스별 탐욕적 IoU 매칭(`IoU > 0.05`)으로 파생 `track_id`를 부여합니다.
  - 단일 객체 시퀀스는 `track_id = 1`이 일관되게 유지되며, 조류 무리(`V_BIRD_009` 등)처럼 근접 교차가 빈번한 다중 객체 시퀀스는 추적 평가 정답(GT)으로 사용하기 전 검수가 필요합니다.

## 7. 카메라 움직임(Camera Motion) 여부 및 고정형 시스템 영향 분석

### 7.2 고정형 관측 시스템(Fixed Camera System)에 미치는 영향

| 기술 영역 | 영향 분석 | 대응 및 권장 전략 |
|---|---|---|
| **외형 기반 탐지기 (CNN/YOLO 등)** | 단일 프레임 외형 특징을 학습하므로 카메라 모션 유무에 덜 민감하며 다양한 배경 학습에 유리함. | 탐지기 학습에는 전체 영상을 활용 가능. |
| **배경 차분 / 프레임 차분** | 카메라 패닝/줌이 있는 영상에서는 배경 전체가 움직여 전경 분리가 실패함. | 움직임 기반 후보 영역 분석 적용 시 카메라 고정 시퀀스만 선별하거나 전역 모션 보정 필요. |

## 8. 영상 단위 Train / Validation / Test 분할 결과

### 8.1 분할 기본 원칙

> [!IMPORTANT]
> **프레임 단위 무작위 셔플링(Random Shuffle) 분할은 엄격히 금지됩니다.**
> 인접 프레임 간의 배경, 조명, 기종 유사도로 인해 Train과 Test 간 심각한 데이터 누수(Data Leakage)가 발생합니다. 반드시 **영상(Video) 단위 분할**을 적용합니다.

### 8.2 센서 분리 계층화 분할 (`SplitGenerator`, seed=42)

- **계층화 기준 (`stratification_axes`)**: `(sensor, primary_class, distance_bin)`
  - `--sensor V` 옵션으로 RGB(`V`)와 열화상(`IR`) 도메인이 섞이지 않도록 분리 분할합니다.
- **복수 드론 영상 고정 배치**:
  - 다중 드론 시퀀스 5개(`V_DRONE_005, 099, 106, 107, 108`)는 다중 객체 추적(MOT) 및 근접 비행 한계 평가를 위해 Test 세트에 고정 배치합니다.
- **RGB 285개 시퀀스 실제 분할 결과**:
  - **Train**: **198개** 시퀀스
  - **Validation**: **45개** 시퀀스
  - **Test**: **42개** 시퀀스 (단일 타겟 계층화 배정 37개 + 다중 드론 5개)
