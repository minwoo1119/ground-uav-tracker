# DroneDetectionThesis 데이터셋 적합성 분석 및 검토 보고서

## 1. 개요 및 목적

본 문서는 지상 고정 RGB 카메라 기반 소형 드론 탐지·추적 시스템의 1차 학습 및 검증용 후보 데이터셋인 **DroneDetectionThesis(Halmstad University)** 데이터셋의 적합성을 체계적으로 검증한 기술 보고서입니다.

- **데이터셋 저장소**: [DroneDetectionThesis/Drone-detection-dataset](https://github.com/DroneDetectionThesis/Drone-detection-dataset)
- **원저자 및 논문**: Fredrik Svanström et al. (Halmstad University), *"A Dataset for Multi-Sensor Drone Detection"*, Data in Brief (2021) / ICPR 2020.
- **검토 목적**: 
  1. 지상 고정 RGB 카메라 기반 소형 드론 탐지·추적 목표에의 부합 여부 검증
  2. 영상 및 라벨 파일 구조, 크기, 클래스별 분포 분석
  3. MATLAB `.mat` 라벨의 Python 파싱 가능성 및 `mcos-decoder` 호환성 심층 검증
  4. Bounding Box 구성 및 Tracking ID 지원 여부 확인
  5. 카메라 모션(움직임) 존재 여부 및 고정 카메라 모델 학습 영향 분석
  6. 영상 단위 데이터 분할 전략 및 라이선스/재배포 조건 확인

## 3. MATLAB `.mat` 라벨 구조 및 Python 파싱 방안

### 3.1 MATLAB `groundTruth` MCOS 직렬화 문제

라벨 파일(`.mat`)은 단순한 MATLAB 행렬이나 구조체(struct)가 아닙니다. MATLAB Computer Vision Toolbox의 `groundTruth` MCOS(MATLAB Class Object Storage) 객체로 저장되어 있습니다.

- **표준 파이썬 라이브러리의 한계**:
  `scipy.io.loadmat`, `pymatreader`, `mat73` 등으로 로드할 경우 `gTruth` 변수는 메타데이터 헤더만 담긴 `MatlabOpaque` 객체로 반환되며, 실제 프레임별 Bounding Box 데이터는 내부 바이너리 버퍼인 `__function_workspace__`에 압축되어 은닉됩니다.
- 이는 저장소 Issue #3 및 SciPy issue #22736으로도 보고되어 있으며, 일반적인 파이썬 스크립트로는 접근이 불가능합니다.

### 3.2 Python 해석 방안 비교

| 방안 | 설명 | 장점 | 단점 | 권장 여부 |
|---|---|---|---|---|
| **A. `mcos-decoder` (PyPI)** | 순수 파이썬 MAT5 스트림 역공학 라이브러리 | 외부 의존성 최소 (NumPy/SciPy), MATLAB 불필요 | **Video_V에 심각한 호환성 결함 존재** (아래 4절 상술) | 단독 사용 불가 (수정 필수) |
| **B. `mat-io` (PyPI)** | MCOS 범용 파서 | 범용 MCOS 속성 트리 탐색 가능 | 무거운 의존성, `groundTruth` 특화 추출 로직 직접 구현 필요 | 대안 후보 |
| **C. MATLAB 공식 엔진/변환 스크립트** | MATLAB 런타임을 이용해 CSV/JSON으로 일괄 익스포트 | MathWorks 공식 API로 100% 무결성 보장 | MATLAB 라이선스 필수, 자동화 파이프라인 구축 어려움 | 보유 시 1회성 변환용으로 우수 |
| **D. 저장소 내장 경량 MAT5 전용 파서** | MAT5 바이너리 스트림을 5열 스트라이드로 직접 디코딩하는 파이썬 스크립트 | 의존성 제로(표준 라이브러리+numpy), Video_V 완벽 호환, 완전 제어 가능 | 파서 유지보수 책임 | **강력 권장** |

## 4. `mcos-decoder`의 Video_V(RGB) 호환성 검증 결과 (중요 발견)

저장소 README에 안내된 `mcos-decoder`(Burak Ozdemir, 2026)의 호환성을 검증하기 위해 바이너리 MAT 스트림을 역공학하여 심층 분석하였습니다.

### 4.1 핵심 발견 사항 (Critical Finding)

> [!WARNING]
> `mcos-decoder`는 Halmstad 데이터셋의 **Video_IR(365개 영상)에 대해서만 검증**되었으며, **Video_V(RGB 285개 영상)에 그대로 사용할 경우 라벨 오분류 및 다중 객체 누락이 발생**합니다.

#### 결함 원인 분석

1. **MATLAB `LabelData` 타임테이블의 열(Column) 구성**:
   MATLAB `groundTruth`의 타임테이블은 5개 열로 구성됩니다:
   - `Col 0`: Time (타임스탬프 메타데이터, 72바이트)
   - `Col 1`: AIRPLANE (80바이트 bbox 또는 48바이트 빈 셀)
   - `Col 2`: BIRD (80바이트 bbox 또는 48바이트 빈 셀)
   - `Col 3`: DRONE (80바이트 bbox 또는 48바이트 빈 셀)
   - `Col 4`: HELICOPTER (80바이트 bbox 또는 48바이트 빈 셀)

2. **`mcos-decoder`의 단순 순회 결함**:
   - `mcos-decoder`는 깊이 5(depth 5)의 원소를 단순히 순회하면서 `size == 80`이면 Bounding Box로 취급하고, `size == 112`이면 빈 프레임(`None`)으로 간주합니다.
   - 단일 드론만 등장하는 `V_DRONE_001` 같은 영상에서는 `[72B, 48B, 48B, 80B, 48B]` 형태로 배치되어 운 좋게 80B 원소 하나만 걸러지지만, **클래스 열 인덱스를 확인하지 않으므로 다중 타겟 또는 다른 클래스가 혼재될 때 라벨이 붕괴**됩니다.

3. **다중 객체(Multi-target) 영상에서의 치명적 오류**:
   - `V_DRONE_106`, `V_DRONE_107`, `V_DRONE_108`, `V_BIRD_009`, `V_HELICOPTER_040` 등 복수 객체가 등장하는 영상에서는 한 프레임에 2개 이상의 박스가 저장됩니다.
   - MATLAB 바이너리에서 2개 박스는 `112바이트 (2x4 double)`, 3개 박스는 `144바이트 (3x4 double)`, 4개 박스는 `176바이트`, 5개 박스는 `208바이트`로 저장됩니다.
   - `mcos-decoder`는 `112B`를 빈 셀(Target absent)로 하드코딩하고 `144B` 이상은 아예 무시하므로, **2개 이상의 드론이 나오는 핵심 프레임을 전부 '타겟 없음(None)'으로 잘못 파싱하거나 버리는 치명적 결함**이 발생합니다.

4. **빈 프레임 처리 결함**:
   - Video_V에서 타겟이 없는 빈 셀은 `48바이트 (0x0 double)`로 저장됩니다.
   - `mcos-decoder`는 48B를 인식하지 않으므로, 드론이 화면 밖으로 나갔다 들어오는 영상의 경우 프레임 인덱스 싱크가 앞으로 밀려 영상과 라벨의 시간축이 완전히 어긋납니다.

### 4.2 기술적 대응 방안

`mcos-decoder` 패키지를 그대로 `pip install`하여 사용하는 것은 부적합하며, 본 프로젝트에서 사용할 변환 스크립트는 **행 단위 5열 스트라이드(Stride)를 보장하고 `(N x 4)` 크기의 가변 double 배열을 디코딩할 수 있는 보완 파서**로 구현해야 합니다.

## 5. Bounding Box 구성 및 Tracking ID 유무

### 5.1 Bounding Box 구성 형식

- **좌표 체계**: `[x, y, width, height]` (MATLAB 표준 픽셀 좌표계)
- **자료형**: 64비트 부동소수점 (`double`, 8바이트 x 4 = 32바이트)
- **기준점**: `(x, y)`는 경계 상자의 좌상단(Top-Left) 모서리 픽셀 위치이며, `width`와 `height`는 픽셀 단위 너비와 높이입니다.
- **값 검증**: 바이너리 디코딩 샘플 결과 정상 범위의 영상 좌표(예: `26.8, 118.3, 28.6, 15.3`)가 저장되어 있음을 확인하였습니다.

### 5.2 Tracking ID 존재 여부

- **Tracking ID 없음 (미존재)**:
  - 라벨 파일 내부에는 각 프레임별 `[x, y, w, h]` 좌표만 존재하며, 객체 추적 식별자(Track ID / Instance ID) 필드는 존재하지 않습니다.
- **영향 및 처리 전략**:
  - **단일 객체 영상 (대다수)**: 영상 전체에 단 1개의 드론만 등장하므로, 암묵적으로 `Track ID = 1`로 간주하여 단일 객체 추적기(SOT) 평가 데이터로 즉시 활용 가능합니다.
  - **복수 객체 영상 (`V_DRONE_005, 099, 106, 107, 108` 등)**: 2대 이상의 드론이 동시에 등장하므로, 연속 프레임 간 IoU(Intersection over Union) 기반 헝가리안 매칭(Hungarian Matching)을 적용하여 사후적으로 Track ID를 부여해야 다중 객체 추적(MOT) 데이터로 활용할 수 있습니다.

### 6.2 전수 객체 크기 분포 분석 방법 설계

전체 비디오를 다운로드하지 않고도, 4.5MB에 불과한 `*.mat` 라벨 파일만을 파싱하여 정량적 객체 크기 통계를 산출할 수 있습니다:
1. `V_*_LABELS.mat` 전체를 순회하며 유효 Bounding Box의 `(width, height)` 추출
2. 객체 픽셀 면적 `Area = width * height` 산출
3. COCO 기준 소형/중형/대형 분류:
   - Small ($Area < 32^2 = 1024 \text{ px}^2$)
   - Medium ($1024 \le Area \le 96^2 = 9216 \text{ px}^2$)
   - Large ($Area > 9216 \text{ px}^2$)
4. 향후 데이터 변환 스크립트 작성 시 이 통계 산출 모듈을 포함하도록 설계합니다.

## 7. 카메라 움직임(Camera Motion) 여부 및 고정형 시스템 영향 분석

### 7.1 카메라 모션 조사 결과

메타데이터 분석 및 논문 내용 확인 결과, 원본 영상에는 다음과 같은 카메라 움직임이 포함되어 있습니다:

1. **외부 YouTube 수집 영상 (동적 카메라)**:
   - `V_HELICOPTER` 중 38개 영상(62.3%)과 `V_AIRPLANE` 중 11개 영상(18.6%)이 YouTube 채널(`SK678387`)에서 수집된 영상입니다.
   - 이 영상들은 지상 촬영자가 망원 렌즈로 비행체를 수동 패닝(Panning), 틸팅(Tilting), 줌(Zooming)하며 추적한 영상입니다.
2. **저자 직접 촬영 영상 (반고정 및 수동 추적)**:
   - 드론 영상의 경우 삼각대(Tripod)를 사용하여 촬영되었으나, 드론이 원거리로 비행함에 따라 삼각대 헤드를 수동 회전시켜 드론을 화면 중앙에 유지하도록 조작한 영상이 다수 포함되어 있습니다.

### 7.2 고정형 관측 시스템(Fixed Camera System)에 미치는 영향

| 기술 영역 | 영향 분석 | 대응 및 권장 전략 |
|---|---|---|
| **외형 기반 탐지기 (YOLO/CNN)** | **긍정적 영향**: 카메라 회전 및 줌으로 인해 배경 텍스처, 조명 각도, 스케일 변화가 풍부해져 딥러닝 탐지 모델의 일반화(Generalization) 성능 향상에 기여함. | 탐지기 학습에는 전체 영상을 제약 없이 활용 가능. |
| **배경 차분 (Background Subtraction)** | **치명적 부정적 영향**: 카메라가 움직이면 GMM, MOG2 등 고정 배경 모델링 알고리즘이 화면 전체를 전경(Foreground) 움직임으로 오인식함. | 카메라 움직임이 있는 시퀀스는 고정 카메라용 배경 차분 알고리즘 평가 데이터셋에서 제외 필수. |
| **움직임 기반 후보 추출 (Frame Diff / Optical Flow)** | **부정적 영향**: 드론을 화면 중앙에 두고 카메라를 패닝하면 드론의 화면 내 상대 속도는 0에 수렴하고 배경이 고속 이동함. | 움직임 필터링 학습 시 카메라 모션 보정(Global Motion Compensation)이 선행되지 않으면 드론이 필터링에서 탈락할 위험 존재. |
| **추적기 (Tracker / Kalman Filter)** | **주의 필요**: 고정 카메라에서는 물리적 등속도 모델이 성립하지만, 카메라 패닝 시 화면 내 가속도가 관측자 손 떨림에 영향을 받음. | 추적기 평가 시 "카메라 완전 고정 시퀀스"와 "패닝 시퀀스"를 분리하여 평가 지표 측정 필요. |

## 8. 영상 단위 Train / Validation / Test 분할 전략 제안

### 8.1 분할 기본 원칙

> [!IMPORTANT]
> **프레임 단위 무작위 셔플링(Random Shuffle) 분할은 엄격히 금지됩니다.**  
> 인접 프레임 간의 배경, 조명, 기종 유사도로 인해 Train과 Test 간 심각한 데이터 누수(Data Leakage)가 발생하여 테스트 정확도가 비현실적으로 과대평가됩니다. 반드시 **영상(Video) 단위 분할**을 적용해야 합니다.

### 8.2 제안하는 계층화 분할 (Stratified Video-level Split)

- **분할 비율**: Train 70% (~200개), Validation 15% (~42개), Test 15% (~43개)
- **층화 배분 기준 (3-Axis Stratification)**:
  1. **클래스 균등 배분**: 4개 클래스 각각에 대해 70 : 15 : 15 비율 적용
  2. **거리 구간(Distance Bin) 균등 배분**: CLOSE, MEDIUM, DISTANT 비율을 각 세트에 동일 비율로 배분
  3. **드론 기종 분산**: F450, Hubsan, Phantom 기종이 Train/Val/Test에 모두 고루 포함되도록 배분

| 데이터 세트 | 영상 수 (전체 285개 기준) | 주요 역할 |
|---|---|---|
| **Train (70%)** | 약 200개 영상 | 단일 프레임 객체 탐지 모델 가중치 학습 |
| **Validation (15%)** | 약 42개 영상 | 학습 중 하이퍼파라미터 튜닝, 오버피팅 감지, 조기 종료(Early Stopping) |
| **Test (15%)** | 약 43개 영상 | 최종 mAP 평가, 오탐(False Positive)률 검증, 추적기 엔드투엔드 벤치마크 |

- **복합 기종 영상 처리**: 다중 드론 영상(`V_DRONE_005, 099, 106, 107, 108`) 5개는 Test 세트에 배정하여 다중 드론 환경에서의 추적 및 탐지 한계 테스트용으로 분리할 것을 제안합니다.

## 11. 확인되지 않은 사항 (미확인 명시)

추측으로 확정하지 않고 미확인으로 남겨두는 항목은 다음과 같습니다:

1. **개별 영상의 인코딩 규격 (FPS, 해상도, 코덱)**:
   - 전체 비디오를 로컬로 다운로드하지 않았으므로, 285개 영상의 개별 해상도(1080p, 720p 등) 및 가변 프레임레이트(VFR) 여부는 실제 다운로드 검증 전까지 **미확인**입니다.
2. **배경 날씨 및 기상 조건 정량 데이터**:
   - `Video_dataset_description.xlsx`에는 거리와 기종만 명시되어 있으며, 역광, 구름, 안개 등 배경 환경 조건의 정량적 태그는 **미확인** 상태입니다.
3. **단일 객체 영상 내 일시적 가려짐(Occlusion) 발생 여부**:
   - 새나 나무 등에 의해 드론이 가려지는 프레임의 존재 여부는 영상 프레임 추출 전까지 **미확인**입니다.

   - YOLO txt 포맷 단독 변환 vs 마스터 JSON 기반 다중 포맷(YOLO + MOT) 생성 방식 선택
