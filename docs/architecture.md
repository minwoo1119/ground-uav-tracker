# 아키텍처

## 목표와 경계

초기 구조의 목표는 영상 입출력, 탐지 런타임, 추적 알고리즘을 서로 교체할 수 있게 분리하는 것입니다. 현재 구현은 CPU 메모리의 읽기 전용 프레임 뷰와 동기식 파이프라인 계약만 정의합니다. 특정 카메라 SDK, 영상 디코더, ML 프레임워크 또는 GPU 런타임에는 의존하지 않습니다.

## 데이터 흐름

```text
IFrameSource -> FrameView -> IDetector -> Detection[]
                                      -> ITracker -> Track[]
                                                  -> IResultSink
```

`TrackingPipeline`은 위 순서와 결과 집계를 담당합니다. 각 어댑터의 생성과 설정은 애플리케이션 계층의 책임입니다.

## 모듈

- `gut_core`: 공용 데이터 구조, 기하 연산, 포트 인터페이스, 파이프라인 조정 로직
- `ground-uav-tracker`: 사용자 명령과 구성을 담당하는 CLI. 현재는 모델 없는 `self-check`만 제공
- `gut_tests`: 외부 테스트 프레임워크 없이 핵심 계약을 검증하는 테스트 실행 파일

## 주요 설계 원칙

- `FrameView`는 픽셀을 소유하지 않습니다. 소스가 다음 프레임을 요청받기 전까지 메모리를 유효하게 유지해야 합니다.
- 타임스탬프는 단조 증가 시간축을 전제로 한 마이크로초 단위 값입니다. 실제 clock과 epoch 선택은 입력 어댑터가 담당합니다.
- 좌표는 픽셀 기준이며 바운딩 박스는 좌상단 `(x, y)`와 양수인 `(width, height)`로 표현합니다.
- 탐지/추적 구현에서 발생한 예외는 파이프라인이 삼키지 않습니다. 잘못된 프레임은 `std::invalid_argument`로 즉시 거부합니다.
- 현재 실행 모델은 단일 스레드, 프레임 단위 동기 처리입니다. 비동기 큐와 백프레셔는 성능 요구가 정해진 후 도입합니다.

## 의도적으로 제외한 항목

모델 선택과 다운로드, 데이터셋, 학습, 추론 백엔드, TensorRT 엔진 생성, 카메라/영상 파일 어댑터, 실제 추적 알고리즘은 이번 단계에 포함하지 않습니다.
